
# Frequently Asked Questions (FAQ)

## 1. What is Markdown?
Markdown is a lightweight markup language used to format plain text using simple symbols. It is commonly used for README files, technical documentation, and user guides.

## 2. How do you create headings and lists?
Use `#` symbols to create headings (`#` for the main heading and `##` for a subheading). Use hyphens (`-`) for unordered lists and numbers for ordered lists.

## 3. How do you add links and images?
Use `[Link Text](URL)` to add hyperlinks. Use `![Alt Text](image-path)` to insert images, where alt text describes the image.

## 4. How do you create tables and code blocks?
Use pipes (`|`) to separate table columns and hyphens (`-`) to create the header separator. Use three backticks before and after a code block to display code.

## 5. How do relative image paths work?
Relative paths specify an image location based on the current Markdown file's folder. For example, `../Img/Sample Image.png` moves up one directory and then into the Img folder.

## 6. How do you organize Markdown project folders?
Organize documentation files in a folder such as `Docs` and supporting images in a separate folder such as `Img`. Use meaningful file names and consistent folder structures.

## 7. What is Git, and how is it used with Markdown?
Git is a version control system that tracks changes to files. It helps technical writers manage documentation revisions, collaborate with team members, and maintain project history.

## 8. How do you stage, commit, and publish documentation?
Use `git add <filename>` to stage changes, `git commit -m "message"` to commit them, and `git push` to upload the committed changes to the remote repository.

## 9. What is a pull request?
A pull request (PR) is a request to review and merge changes from one branch into another. It allows team members to review, comment on, and approve documentation updates before merging.

## 10. How do you troubleshoot broken links and images?
Verify the file name, spelling, capitalization, file extension, and relative path. Also check that the linked file exists in the specified folder.
